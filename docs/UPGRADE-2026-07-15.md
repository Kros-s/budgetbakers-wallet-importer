# Upgrade 2026-07-15 — instrucciones de despliegue

Instrucciones para el agente/sesión que instala esta actualización en la máquina
donde corre el bot (`com.bbw-bot` vía launchd). Los 8 commits de esta fecha
corrigen: pérdida de mensajes por Markdown inválido, pérdida de respuestas a
aclaraciones, amnesia de sesión tras reinicios, procesos duplicados, categorías
rechazadas por variantes de nombre, falsos positivos de duplicados, y agregan
reglas aprendidas persistentes + soporte de transferencias en los prompts.

## Pasos

1. **Pull y build**

   ```bash
   cd <repo>
   git pull --ff-only
   npx tsc            # el LaunchAgent ejecuta dist/main.js, no tsx
   npx tsx --test "src/tests/**/*.test.ts"   # esperado: 37/37 pass
   ```

2. **Sembrar las reglas aprendidas** — `data/` está en gitignore, así que este
   archivo NO llega con el pull. Crear `data/bot/learned-rules.md` con este
   contenido exacto (si ya existe con reglas nuevas, conservarlas y solo
   agregar las que falten):

   ```markdown
   # Reglas aprendidas (inyectadas en cada análisis de correo)

   - La tarjeta Costco Banamex terminación ****975 a nombre de MARCO MAYEN es DEL USUARIO (el usuario ES Marco Mayen). Sus cargos van a la cuenta "Costco". NUNCA preguntar de quién es.
   - Cargos de "Cashi": son de un familiar — ignorarlos por completo (NO_TRANSACTION).
   - Pedidos de Walmart: a veces son de familiares. Si el correo no trae método de pago, preguntar con qué cuenta se pagó; si el usuario dice que es de un familiar, ignorar.
   - NO importar ganancias/intereses/rendimientos de Mercado Pago — el usuario los registra manualmente a fin de mes (NO_TRANSACTION).
   - "American Express" = tarjeta Amex Gold; "Platinum Credit Card" = Amex Platinum. No confundirlas.
   - La nómina entra a Bancomer y luego se traspasa a Banorte. Nunca registrar income directo en Banorte.
   - Todo registro creado por el bot lleva en note el marcador "[Claude YYYY-MM-DD]" (fecha del día del import).
   - Mensualidad de natación (Club de Golf Pachuca, cargo en Costco) → categoría "Active sport, fitness".
   ```

3. **Matar cualquier proceso suelto del bot** (el candado de instancia es nuevo;
   procesos viejos no lo respetan):

   ```bash
   pgrep -fl "dist/main.js"        # revisar cuántos hay
   launchctl kickstart -k gui/$(id -u)/com.bbw-bot
   pgrep -fl "dist/main.js"        # debe quedar exactamente UNO
   ```

   Si tras el kickstart sigue habiendo más de uno, el sobrante es un proceso
   manual: `kill <pid>` del que NO gestiona launchd.

4. **Verificar**

   ```bash
   cat data/bot/bot.pid            # debe existir y coincidir con el pid vivo
   ls -t data/bot/bot-*.log | head -1 | xargs tail -20   # arranque sin errores
   ```

   Smoke test en Telegram: mandar un texto tipo "gasté 50 en oxxo con costco" —
   debe responder con propuesta CSV y botones Confirmar/Cancelar.

## Notas de comportamiento nuevas

- Si el bot detecta un hecho estable en una respuesta del usuario, appendea a
  `learned-rules.md` y avisa "🧠 Regla guardada: …". Ese archivo es la memoria
  del flujo de correos; respaldarlo fuera de git (no se versiona).
- Las sesiones de Claude persisten en `data/bot/sessions.json`; `/reset` en el
  chat sigue limpiando la conversación si hiciera falta.
- El resumen de las 21:00 ya no se envía en días sin movimientos.
- Un segundo arranque del bot muere con "Another bot instance (pid N) is
  already running" — es intencional, no un bug.
- Transferencias entre cuentas propias: Claude ahora propone DOS filas CSV con
  la misma fecha/hora y categoría "Transfer, withdraw" (el importador las
  enlaza como par). Una sola fila Transfer se rechaza por diseño.
